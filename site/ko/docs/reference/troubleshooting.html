문제 해결 & 거절 사유별 복구 매트릭스

모든 오류와 의도적 거절 사유에 대한 원인 진단과 즉시 복구 절차.

Lancet의 모든 거절은 조용히 덮어쓰지 않고 종료 코드 2와 구체적인 원인 메시지를 반환합니다. 증상별 해결 절차를 바로 찾으세요.

편집 · 패치 · 이름 변경 거절#

증상 / 오류근본 원인정확한 복구 절차
edit / patch / rename에서 status: "conflict"--rev를 읽은 뒤 디스크 파일이 변경됨lancet read <FILE> --json으로 새 내용과 rev를 다시 읽어 수정을 재계산해 적용합니다.
edit --find 거절 (0회 또는 2회 이상 일치)리터럴 문자열이 파일 내에서 고유하지 않음오류에 출력된 줄 번호를 보고 --find 앞뒤 문맥을 넓히거나 의도한 전체 변경이면 --all을 추가합니다.
edit --symbol 후 문서 주석·어트리뷰트 사라짐--symbol은 read --symbol처럼 위쪽 ///·#[attr]까지 포함함--with/--with-file에 주석과 어트리뷰트를 포함하거나 본문 줄 범위(--lines)만 지정하세요.
구문 오류 증가 거절편집·패치 결과 Tree-sitter 구문 오류 수가 늘어남dry-run diff에서 닫히지 않은 괄호·따옴표를 점검하고, 의도된 중간 단계일 때만 --allow-syntax-errors를 씁니다.
lancet rename 거절 (unsupported)최상위/필드/메서드/Python 매개변수/매크로/JSX 태그/섀도잉거절 목록을 확인하고 lancet refs + lancet edit --edits나 LSP를 사용하세요.
lancet patch 바이너리/복사 diff 거절패치에 Binary files 또는 copy from 포함텍스트 hunk만 남겨 파이프하세요.

검색 · AST · 순회 오류#

증상 / 오류근본 원인정확한 복구 절차
LQL에서 status: "invalid_query"알 수 없는 필터, 닫히지 않은 따옴표, 연산자 누락lancet parse '<QUERY>'를 실행해 오류 pos 바이트 위치를 확인하세요.
ast --rewrite --apply가 --limit 거절개수 제한과 자동 적용의 조합은 의도치 않은 부분 수정을 유발함--limit을 빼고 --path GLOB로 대상 파일을 좁히세요.
ast 'if ($C) $S'가 if ... else 누락Lancet은 if와 if-else AST 노드를 엄격히 구분함else 분기까지 포함하는 두 번째 패턴을 함께 실행하세요.
lancet rg -P 실패PCRE2 전후방 탐색·역참조 미지원룩어라운드 없는 Rust regex나 LQL before() / NOT으로 작성하세요.
lancet fd에 경로 2개 전달 시 오류lancet fd [PATTERN] [PATH]는 최대 1개 PATH만 허용디렉터리마다 나눠 호출하거나, 패턴이 폴더명과 같다면 -p PATTERN을 쓰세요.

인덱스 · 문서 · MCP 문제#

증상 / 메시지근본 원인정확한 복구 절차
--trust-index에서 방금 수정한 파일이 검색 안 됨--trust-index는 설계상 디스크 stat 검사를 건너뜀--trust-index를 빼고 auto 모드를 쓰거나 lancet index .로 동기화하세요.
Windows에서 크기·mtime 동일한 수정 놓침Windows에서 Rust stdlib이 mtime과 size만 제공함타임스탬프를 되돌리는 도구 실행 후엔 lancet index .나 --no-index를 쓰세요.
lancet rg가 PDF / .docx 내용을 못 찾음lancet rg는 rg 호환성 때문에 어댑터가 기본 OFFlancet rg --docs를 붙이거나 기본 LQL 검색(lancet 'query')을 쓰세요.
스캔 PDF / 이미지 텍스트가 비어 있음임베디드 텍스트 레이어가 없는 이미지--ocr을 붙이고 PATH에 pdftoppm과 tesseract가 있는지 확인하세요.
MCP 목록에 lancet_edit / patch / rename 없음lancet mcp --read-only로 실행됨편집이 필요하면 --read-only 없이 서버를 다시 시작하세요.
