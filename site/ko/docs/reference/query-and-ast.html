Lancet Query Language(LQL v0.1) & 24개 언어 AST 명세

EBNF 정식 문법, 매처·스코프 의미론, 24개 --lang 별칭, AST 메타변수 규칙.

Lancet Query Language(LQL v0.1)는 결정적인 중간 표현(IR)으로 컴파일되어 인덱스 후보와 풀스캔에서 동일하게 평가됩니다. 알 수 없는 연산자나 필터는 조용히 무시하지 않고 정확한 바이트 위치와 함께 status: "invalid_query"를 반환합니다.

LQL v0.1 정식 문법#

EBNF
query   := ["find"] expr ("in" scope)* ("|" stage)*
expr    := or_expr
or_expr := and_expr ("OR" and_expr)*
and_expr:= unary (("AND")? unary)*          # 공백으로 인접한 항은 암묵적 AND
unary   := "NOT" unary | primary
primary := string
         | word                            # 따옴표 없는 단일 토큰 -> 리터럴
         | "(" expr ")"
         | "regex(" string ")"
         | "fuzzy(" string ["," uint] ")"  # k는 0..=3, 기본 1
         | "symbol(" string ")" | "symbol:" (string | word)
         | "near(" matcher "," matcher "," uint ")"
         | "before(" matcher "," matcher "," uint ")"

matcher := string | word | "regex(" string ")" | "fuzzy(" string ["," uint] ")"
         | "symbol(" string ")" | "symbol:" (string | word)

scope   := ("line" | "block" | "file" | "function"
         |  "type:" values | "ext:" values | "path:" values)+
values  := value | "(" value ("," value)* ")"

stage   := "limit" uint                    # uint >= 1
         | "count"
         | "files"
         | "group" "file"
         | "expand" ("parent" | "unit" | "context:" uint)
         | "sort" ("count" ["asc" | "desc"] | "path")
         | "terms" ["top:" uint]           # 1..=100, 기본 15
         | "budget" ["tokens:"] uint       # uint >= 1

연산자 우선순위는 NOT > AND(명시적 또는 암묵적) > OR입니다. lancet parse '<QUERY>'로 정규화된 쿼리와 JSON IR을 바로 확인할 수 있습니다.

매처, 스코프 & 파이프 단계 의미론#

구문정확한 동작
"text" / 일반 토큰대소문자 무시(Unicode simple case folding) 부분 문자열 매치.
regex("pat")멀티라인 모드 Rust regex(^/$가 줄 경계). 기본 대소문자 구분((?i)로 해제).
fuzzy("word", k)문자 단위 레벤슈타인 거리 0 <= k <= 3(기본 1) 단어 토큰 매치, 건전한 q-gram 임계값으로 인덱스 가속.
symbol("name") / symbol:nameTree-sitter 심볼 정의 정확 매치(대소문자 무시; .rs, .py, .js, .ts, .tsx, .go).
near(a, b, d) / before(a, b, d)단위 안에서 토큰 거리 |tok(b) - tok(a)| <= d(before는 b가 반드시 a 뒤).
in file / in block / in linefile(기본), 빈 줄 없는 문단(block), 단일 줄(line; 매치 전체 [start, end)가 단위 안에 있어야 함).
in functionTree-sitter 함수·메서드 AST 노드(.rs, .py, .js, .ts, .tsx, .go); 결과에 symbol 채움.
type: / ext: / path:같은 카테고리 값은 OR, 서로 다른 카테고리는 AND. type:는 code, document, spreadsheet, config, log, data, archive, image, other.
| limit / files / count / group file간결한 투영 및 결정적 결과 수 제한.
| expand / sort / terms / budget상위 문맥 확장, 횟수/경로 정렬, 동시 출현 어휘 추출, 추정 토큰 상한 적용.

메타변수 & 리라이트 규칙#

  • $VAR: 명명된 단일 AST 노드에 매치; 같은 이름을 반복하면($X == $X) 구조가 동일해야 합니다.
  • $_: 익명 단일 노드 와일드카드(치환 템플릿에 캡처되지 않음).
  • $$$ARGS: 0개 이상의 형제 AST 노드(백트래킹 폭주를 막기 위해 메모이제이션과 단계 예산으로 제한).
  • 문장 메타변수: C 계열 언어에서 if ($C) $S, { $$$B }가 동작하며, if ($C) $S는 else 없는 if만 엄격히 매치합니다(ast-grep과 다른 점).
  • 리라이트 안전 규칙: --rewrite는 기본적으로 dry-run이며, --apply는 --limit과 함께 쓸 수 없고, 한 파일 내 중첩 매치는 건너뛰어 skipped_overlaps에 기록됩니다. --lang cpp는 .cpp/.cc 외에 .h 헤더도 스캔합니다.
