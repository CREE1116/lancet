시작하기

기존 도구(rg, fd, ast-grep, sed, patch, rga)에서 전환하기

ripgrep·fd·ast-grep의 익숙한 사용감을 유지하면서 줄 밀림과 덮어쓰기 사고를 없앱니다.

기존 작업 습관을 한 번에 바꿀 필요는 없습니다. lancet rg와 lancet patch로 익숙한 플래그와 diff 파이프를 그대로 쓰면서, 도구 사이의 이음새에서 오류가 생기는 지점부터 LQL·AST·--rev CAS를 도입할 수 있습니다.

ripgrep(rg)에서 오셨다면#

lancet rg는 ripgrep의 플래그, Rust regex 엔진, 무시 파일 순회, 종료 코드(0 매치, 1 없음, 2 오류), 출력 형식을 그대로 구현했으며 68개 엣지 케이스 픽스처와 Linux 커널 전체 쿼리를 ripgrep 15.2와 바이트 단위로 대조 검증했습니다.

ripgrep 명령lancet 대안정확한 동작 차이
rg foo srclancet rg foo src파이프 시에도 -n이 기본 ON; 끄려면 -N
rg -i -w -t py toklancet rg -i -w -t py tok-i/-s/-S 마지막 플래그 우선; AST 기반 -S(\W 무시 유지)
rg -g '*.toml' --passthrulancet rg -g '*.toml' --passthru--passthru/-A/-B/-C 마지막 우선; 미일치 파일도 출력
rg --type-add 'web:*.tsx'lancet rg --type-add 'web:*.tsx' -t webname:glob, name:include:a,b 모두 지원
rg -P '(?<=a)b'lancet 'before("a", "b", 1)' 또는 Rust regex-P/PCRE2는 선형 시간·건전한 트라이그램 컴파일을 위해 미지원
rg --pre pdftotext patlancet rg --docs pat외부 프로세스 없이 인프로세스로 PDF·오피스·HWP·압축 검색
lancet rg의 의도적 차이 3가지
  • 항상 경로 요소순 정렬: a/b.txt가 a.txt보다 앞(rg --sort path와 동일).
  • 줄 번호(-n) 기본 ON: 파이프·리다이렉션 때도 켜져 있으며 -N으로 끕니다.
  • 파일명 헤더 없음: 항상 path:line:text 한 줄 형식이며 --color auto는 TTY에서만 색을 입힙니다.

fd / find에서 오셨다면#

fd / find 명령lancet fd 대안비고 및 추가 기능
fd -e rs -d 2 srclancet fd -e rs -d 2 src.lancet 인덱스 활용; [PATH]는 최대 1개
fd -t d -d 2lancet fd --tree --dirs -d 2 .파일 없이 폴더 트리만 간결하게 출력
find . -mtime -7 -type flancet fd -t f --changed-within 7d단위: s, m, h, d, w
find . -name '*.pdf'lancet fd --type-class document확장자 나열 없이 9개 의미 클래스로 필터링
fd config src (패턴이 폴더명과 같을 때)lancet fd -p config src-p/--pattern으로 패턴과 경로를 명확히 구분

ast-grep(sg)에서 오셨다면#

ast-greplancet ast중요한 차이점
sg -p '$X.unwrap()' -l rslancet ast '$X.unwrap()' -l rs패턴에 리터럴이 있으면 .lancet 트라이그램 프리필터로 가속
sg -p 'f($$$A)' -r 'g($$$A)' -Ulancet ast 'f($$$A)' -r 'g($$$A)' --apply--apply 전엔 dry-run diff; --apply는 --limit과 병행 불가
sg -p 'if ($C) $S'lancet ast 'if ($C) $S'엄격한 AST 모양 매치: else 없는 if만 매치(if-else는 별개 노드)
sg -l cpp ...lancet ast ... -l cppLancet cpp는 .cpp/.cc뿐 아니라 .h 헤더도 함께 검색

cat / sed / patch / rga에서 오셨다면#

기존 도구 사슬Lancet 대체해결된 사고
sed -n '10,50p' f.rslancet read f.rs --lines 10:50XXH3-64 rev 반환 + --budget-tokens 상한
rg -n 1회 후 sed -i 2회lancet edit f.rs --edits - --rev REV --apply모든 구간이 원본 줄 번호 기준; 심볼릭/하드 링크·권한 보존
patch -p1 < difflancet patch diff --apply모든 파일 사전 검증, 정확 위치 재배치, CAS 경합 롤백
rga + pdftotext/pandoclancet 'pat' + lancet read f.pdf -p 2같은 추출 파이프라인으로 검색 줄 == 읽기 줄

전문 도구를 그대로 써야 하는 경우#

의도적인 범위 경계
  • 버전 관리: git은 그대로 쓰세요. Lancet은 .gitignore를 준수하며 git diff를 lancet patch로 적용합니다.
  • 여러 파일에 걸친 타입 기반 리팩터링: 공개 API·필드·메서드·Python 키워드 매개변수의 크로스 파일 이름 변경은 LSP(rust-analyzer, tsserver, gopls)를 쓰세요. Lancet의 rename은 단일 파일 로컬 바인딩만 증명해 변경합니다.
