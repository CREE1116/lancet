실전 가이드

컨텍스트를 아끼며 낯선 코드베이스 탐색하기

파일 전체를 읽어 토큰을 낭비하지 않고 다섯 단계로 핵심 코드에 정확히 도달하는 법.

개발자나 AI 에이전트가 컨텍스트 토큰을 낭비하고 길을 잃는 가장 흔한 원인은 파일 전체를 닥치는 대로 읽는 것입니다. Lancet은 수만 개 파일에서 정확히 필요한 줄까지 좁혀 내려가는 5단계 탐색 깔때기를 제공합니다.

1. 파일 소음 없이 폴더 구조 먼저 파악하기#

파일 목록이나 검색을 돌리기 전에 디렉터리 골격부터 확인합니다.

터미널
lancet fd --tree --dirs --max-depth 2 .
lancet fd --changed-within 2d -t f src

--tree에 --dirs(-t d와 동일)를 붙이면 폴더만 계층으로 보여 주어 프로젝트 아키텍처를 수십 줄 안에 파악할 수 있습니다.

2. refs --rank로 핵심 선언 순위 찾기#

낯선 저장소에서는 어떤 클래스·구조체·인터페이스·함수가 실제로 많이 쓰이는지 어휘 참조 수 순위로 바로 뽑아낼 수 있습니다.

터미널
# 가장 많이 참조되는 *Service 클래스 상위 10개
lancet refs --rank '*Service' --kind class src --limit 10

# 디렉터리 내 가장 많이 호출되는 함수 상위 10개
lancet refs --rank '*' --kind function --limit 10 src

# 정의와 참조 위치 상세 조회 (주석·문자열 자동 제외)
lancet refs SearchOptions src --lang rs --json
--rank의 중복 이름 표시 이해하기

글롭에 리터럴(예: Service)이 포함되면 트라이그램 인덱스로 후보를 좁힌 뒤 AST 선언을 수집합니다. 출력에 (name shared by N declarations) 또는 JSON의 definitions > 1이 표시되면 여러 선언이 같은 이름을 공유한다는 뜻입니다.

3. 본문 전에 뼈대만 보기 (outline)#

lancet outline으로 코드 선언 시그니처, 마크다운 제목 목차, 엑셀 시트 목록, 압축 파일 내부 경로와 정확한 줄 범위를 먼저 확인하세요.

터미널
lancet outline src/search.rs
lancet outline docs/architecture.md
lancet outline financial_model.xlsx
lancet outline logs/bundle.zip

4. 여러 쿼리 한 번에 실행(batch) & 파이프 정제#

서로 관련된 여러 질문을 던져야 할 때는 lancet batch로 인덱스와 디렉터리 순회를 딱 1번만 열고 모든 쿼리를 평가합니다. LQL 파이프로 출력을 더 줄일 수 있습니다.

터미널
# 인덱스 열기·워크 1회 공유로 쿼리 3개 동시 실행
lancet batch src \
  -q 'near("retry", "backoff", 20) in function' \
  -q '"Conflict" in ext:rs' \
  -q 'fuzzy("idempotent", 1) | files'

# 동시 출현 상위 키워드 추출 및 토큰 상한 적용
lancet '"trigram" in ext:rs | terms top:10 | budget tokens:1200' src

5. 토큰 예산(budget-tokens) 기반 페이지네이션 읽기#

전체 파일 대신 해당 심볼(문서 주석·어트리뷰트 포함)이나 토큰 상한을 지정해 읽으세요. 잘렸다면 반환된 next_line부터 이어서 읽습니다.

터미널
lancet read src/search.rs --symbol execute_one
lancet read src/search.rs --lines 100:400 --budget-tokens 800 --json
실측 컨텍스트 절감

why-one-tool 실험에서 줄·심볼·토큰 예산을 지정해 읽은 경우 전체 파일 읽기보다 컨텍스트 사용량이 5~30배 줄었으며, 안전한 편집에 필요한 줄 번호와 rev 토큰도 그대로 유지했습니다.
