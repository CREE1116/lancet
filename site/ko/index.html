기능

    
에이전트가 코드베이스에서 하는 모든 일.

    

      

        

        
인덱스 속도, 낡은 결과 없음

        
트라이그램 인덱스가 후보 파일을 고르고, 모든 후보는 전체 스캔과 같은 평가기로 검증합니다. 인덱싱 이후 바뀐 파일은 mtime/size/ctime/inode로 찾아 그 자리에서 스캔합니다. 띄워 둘 데몬이 없습니다.

      

      

        

        
ripgrep과 바이트 단위로 동일

        
lancet rg는 ripgrep의 플래그를 받아 ripgrep과 같은 출력을 냅니다. 코드베이스 8개에서 바이트 단위로 대조했습니다. .gitignore, .rgignore, glob, --type도 똑같이 해석합니다.

      

      

        

        
구조 검색과 치환

        
Tree-sitter 24개 언어에서 lancet ast '$X.unwrap()' --rewrite '$X?'. $$$ARGS와 문장 메타변수도 지원합니다. --apply 전까지 치환은 dry-run diff입니다.

      

      

        

        
정확한 읽기, 작은 컨텍스트

        
read --symbol, 줄 범위, PDF 페이지, 스프레드시트 셀을 토큰 예산 안에서 읽습니다. 같은 조회에서 파일 전체를 읽을 때보다 컨텍스트를 5–30배 적게 썼습니다.

      

      

        

        
여러 에이전트가 함께 써도 안전한 편집

        
edit, patch, AST 치환은 모두 잠금을 건 compare-and-swap 하나를 거쳐 씁니다. 낡은 --rev는 conflict를 받고 아무것도 쓰지 않습니다. 심볼릭 링크·하드 링크·파일 권한은 유지되고, 구문 오류를 늘리는 편집은 거부합니다.

      

      

        

        
문서까지 한 범위로

        
PDF, DOCX, PPTX, XLSX, HWP, EPUB, ZIP, TAR를 압축 폭탄 상한을 두고 프로세스 안에서 추출합니다. .docx의 42번째 줄 검색 결과는 read에서도 42번째 줄입니다.

      

    

  






  

    
벤치마크

    
코드베이스 8개, 언어 7개, ripgrep과 같은 출력.

    
드문 리터럴 쿼리에서 ripgrep 대비 속도 향상. auto는 쿼리마다 최신 여부를 확인하고(기본값), trust는 인덱스만으로 답합니다(--trust-index). 모든 텍스트 결과를 ripgrep 출력과 바이트 단위로 대조했습니다.


    

      

        
ripgrep 대비 속도 향상 (로그 축, 쿼리별 최소–최대)

        
auto (항상 최신)trust (--trust-index)

      

      

      

      

        표로 보기
        

          
코드베이스파일인덱스 빌드 · 크기auto 대 rgtrust 대 rgAST 대 ast-grep

          
        

      

    

    
lancet이 이기지 못하는 곳: 리터럴이 없는 정규식(인덱스로 좁힐 수 없어 ripgrep과 같은 속도이거나 최대 1.4배 느림)과 리터럴이 없는 AST 패턴(ast-grep 속도의 0.6–1.0배). 전체 표와 측정 방법 →

  






  

    
왜 하나의 도구인가

    
도구 체인은 단계와 단계 사이에서 깨집니다.

    
각 행은 실제 도구로 재현했습니다: bench/failure_modes.py.

    

      
도구 체인실제로 일어난 일lancet

      
        
rg -n → sed -i 편집 두 번두 번째 편집이 엉뚱한 줄을 고침, 둘 다 종료 코드 0edit --edits는 원래 줄 번호 기준

        
에이전트 4개: 읽기 → 수정 → 다시 쓰기업데이트 800개 중 600개가 조용히 유실edit --rev: 800개 중 0개 유실

        
낡은 hunk가 섞인 patch -p1한 파일은 바뀌고 한 파일은 거부: 절반만 적용patch: 아무것도 안 씀, conflict

        
sed로 이름 변경주석과 문자열까지 바꿈 (출현의 0.3–11.7%)refs / ast는 코드만 건드림

        
.docx에 rga → pandoc읽은 줄 40개 중 0개에만 검색어가 있음40개 중 40개: 검색과 읽기가 같은 추출 결과를 씀

        
파일 20개 수정 직후의 zoekt새 텍스트는 0개 파일에서 찾고, 지운 텍스트는 20개 파일에서 여전히 찾음auto 모드: 20과 0

        
sed -i / perl -pi하드 링크와 심볼릭 링크를 깨고 권한 0640을 잃음같은 파일 유지: 링크·권한·소유자 보존

# 핵심 흐름은 이렇습니다:

1. 검색:  lancet rg ... / lancet '...쿼리...'
2. 읽기:  lancet read FILE --symbol NAME --json

3. 수정:  lancet edit FILE ... --rev REV --apply
4. conflict(종료 코드 2)면: 다시 읽고, 새 내용에
   변경을 다시 적용해 새 rev로 재시도.
