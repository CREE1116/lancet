Concepts & Design

Architecture, Failure Modes & Honest Benchmarks

Measured across 8 repositories and compared honestly against ripgrep, zoekt, ast-grep, tgrep, grix, and aft.

Tools built separately assume a human bridges the gaps between them. When an autonomous agent chains rg → sed → patch → pdftotext, mismatches turn into silent data loss. Lancet replaces the brittle handoffs inside one binary — and publishes exact benchmarks including where competitors are faster.

7 Failure Modes Reproduced & Eliminated#

  1. Line drift across edits: two sequential sed -i calls from one rg -n hit the wrong line cleanly (exit 0). lancet edit --edits resolves all hunks on original coordinates.
  2. Silent concurrent overwrites: 4 concurrent read-modify-write agents lose 600 / 800 updates silently; lancet edit --rev loses 0 / 800.
  3. Half-applied patches: patch -p1 with one stale hunk mutates file A and rejects file B; lancet patch verifies all files first and rolls back on write races.
  4. Comment/string corruption: sed renames mutate 0.3–11.7% comments/strings; refs and ast ignore them cleanly, and rename re-resolves local scopes.
  5. Document extraction mismatch: rga + pandoc agree on 0 / 40 hit lines inside .docx; Lancet shares one extraction pipeline (40 / 40).
  6. Post-edit index staleness: immediately after editing 20 files, zoekt finds new text in 0 and stale deleted text in 20; Lancet auto reports 20 and 0.
  7. Broken links & modes: sed -i / perl -pi destroy symlinks/hard links and drop mode 0640; Lancet writes symlink targets and updates multiply hard-linked files in-place.

See the full design essay in docs/why-one-tool.md (한국어).

Indexed & Agent Tool Comparison (Honest Tradeoffs)#

Measured via bench/competitors_agents.py across rg, ast-grep, tgrep (disk & daemon serve), grix, aft, tensor-grep, and probe (COMPETITORS.md):

  • Where Lancet leads: 20/20 immediate 0 ms post-edit freshness with zero daemon (aft watcher lag and serverless tgrep score 0/20 at 0 ms); 1/3–1/7× smaller disk index than aft / tgrep (141.8 MB vs 368.5 MB / 955.2 MB on Linux); ~1/3× peak build RAM vs grix (353.5 MB vs 1,001.6 MB on Linux); 20/20 exact rg line-count parity; fastest literal AST search across all 4 tested corpora.
  • Where specialized or daemon tools win: tgrep serve (resident daemon) beats daemonless lancet auto on regex with literal in Rust (119.2 ms vs 508.7 ms) and LLVM (19.9 ms vs 295.8 ms), and on small literal-free regexes in Django (15.4 ms) / Rust (60.9 ms). grix --no-auto-index is faster than lancet --trust-index on Linux rare literal (11.5 ms vs 43.6 ms). Resident aft (587–1,260 MB RAM) is faster on Rust rare literal (8.5 ms vs 73.5 ms). Literal-free regexes and literal-free AST patterns run near rg (down to 1.4× slower) and ast-grep (0.6–1.0×).
